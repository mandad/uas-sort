# uas-sort Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete, feature-complete initial version of uas-sort — a manually launched WinUI 3 app (plus a dry-run CLI) that offloads a DJI Air 3S SD card into a dated, GPS-grouped video library and a flat Lightroom photo folder with verified, never-overwriting copies, an itemised "safe to format?" verdict, and an optional confirmed card cleanup — in one agent pass.

**Architecture:** A UI-free `UasSort.Core` (model, ports, IO guard policy, media probes, time/geo, library index, ledger reading, planning/editing, offload engine, audit, card cleanup) is surrounded by `UasSort.Platform` (the only code that touches disk/Win32/shell), `UasSort.Review` (WinUI-free view models and the map bridge), `UasSort.App` (WinUI 3 shell, pages, WebView2 + MapLibre map pane, composition root) and `UasSort.Cli` (dry-run `plan`). Every file-system call goes through guarded ports; direct file APIs outside Platform fail the build via BannedApiAnalyzers, and tests run against a fake file system with a hydration tripwire and a card-delete tripwire.

**Tech Stack:** .NET 11 (SDK `11.0.100-rc.1.26425.128`) · C# 15 · WinUI 3 / Windows App SDK 2.5.1 component packages · CommunityToolkit.Mvvm 8.4.2 · CommunityToolkit.WinUI Sizers/SettingsControls 8.3.260402-preview2 · WebView2 1.0.4191.47 + vendored MapLibre GL JS 6.11.2 · MetadataExtractor 2.9.3 · GeoTimeZone 6.1.0 · System.IO.Hashing · xUnit v3 (`xunit.v3.mtp-v2` 4.0.1) on Microsoft.Testing.Platform · Native AOT publish.

**Spec:** [`docs/superpowers/specs/2026-09-27-uas-sort-design.md`](../specs/2026-09-27-uas-sort-design.md) (main; wins on conflict) and [`docs/superpowers/specs/2026-09-27-uas-sort-design-reference.md`](../specs/2026-09-27-uas-sort-design-reference.md) (exact types, signatures, rules and test cases). Executors read both. Research and spike code to port: `docs/research/` (notably `spikes/djmd/djmd_gps.py`, `spikes/djmd/synth_test.py`, `spikes/grouping/grouping.py`, `spikes/grouping/test_grouping.py`, `spikes/grouping/replay.py`, `spikes/review-ux/mp4thumb.py`, `spikes/winui/src/**`, `spikes/modern-stack/winui-src/**`, `spikes/map-pane/web/**`).

## Review Focus

Inputs and conditions the spec implies but no spec test names; each has its test in the owning task (marked **[Review Focus]** there).

1. **A card where nothing is new** (every clip and photo already imported or in the ledger) — Review shows an explicit "Nothing new on this card" state with every AlreadyImported group folded (NothingToCopy groups follow the spec's fold rule and stay unfolded), Offload disabled with that reason (`IssueCode.NothingNew`, Blocking), and the verdict can still be computed as Safe. → Part 06 (Planner/issues) and Part 10 (ReviewVm).
2. **Descriptions and existing folder names with Unicode, emoji, trailing dots/spaces, or differing only by case** from an existing folder of the same date — `FolderNamer.Clean` keeps Unicode letters, strips trailing dots/spaces, and a case-only clash becomes an explicit Append ("Folder exists; appending"), never a second folder. → Part 06 (FolderNamer, FolderDecider).
3. **A video root containing non-event folders and loose files** (e.g. `Picture Offload`, `Exports\`, a stray MP4 at `2026\`, `desktop.ini`) — LibraryIndex still matches name+size for newness everywhere, but only `YYYY-MM-DD …` folders become event folders/append targets, and loose files never create a pseudo-folder. → Part 05 (LibraryIndex).
4. **A trip across a DST transition** (e.g. flights on 2026-10-31 and 2026-11-01 with a zone-fitted drone clock on `America/New_York`) — photo stamps in the repeated 01:00–02:00 hour convert with the offset of the nearest video sample, local dates stay correct, and `CheckDate` is raised only within its window. → Part 04 (DroneClock/TimeResolver).
5. **The drone connected over USB exposing two volumes at once** (internal storage and SD card, each with `DCIM\DJI_001`) — the Card stage lists both, never auto-picks when more than one DJI card is present, and each volume is its own run with its own identity. → Part 02 (CardDetector) and Part 10 (CardStageVm).

## Completion criteria (Ref §14)

- The full solution builds with `TreatWarningsAsErrors`.
- `dotnet test --solution uas-sort.slnx` passes: unit, IO guard policy, card cleanup, invariants, performance, newness and ledger, golden replay, synthetic media, fake-FS tripwire, fault injection, Windows integration and view-model tests, and the CLI run.
- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1 -CheckBannedApi` raises every expected RS0030.
- The Native AOT publish passes `--selftest` through the `deploy.ps1` gate on x64 (both runs exit 0; warm first frame ≤ 1 s); a warm first frame slower than the 370 ms ReadyToRun baseline is reported in the completion summary (`slowerThanBaseline`), not a failure.

After that, the user runs the first-real-card acceptance (Ref §13): CLI dry run vs `tests/acceptance/first-card-expected.json`, rehearsal offload to `%TEMP%\uas-sort-rehearsal\{video,photo}`, the real offload, and a cleanup of one old eligible clip.
